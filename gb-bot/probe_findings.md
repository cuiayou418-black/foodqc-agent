## 两个关键认知（排障课，记牢）
- **粗筛会漏报**：脚本只数"中文字占比"，但乱码字符（犌犅 等）也落在中文 Unicode 区间，被误算成正常中文 → GB5009.22、GB5009.257 漏判。
- **阈值有盲区**：GB2716 只有 5 页，没过">5 页"门槛，但正文其实乱码。
- **结论**：自动指标只是线索，最终必须亲眼验证抽出来的字"能不能读"，不能只看"抽出了多少字"。

## 🔴 21:15 实测补充：不是"缺 ToUnicode"，是"映射错乱"（小懒Q）

**原判断有误，此处更正**：上文写的"典型 ToUnicode 缺失"**不准确**。用 PyMuPDF 查字体字典实测：

```
GB2716-2018    font FZXBSK--GBK1-0  enc=Identity-H  ToUnicode=True
GB19641-2015   font SSJ-PK74820001299-Identity-H    ToUnicode=True
GB5009.227-2023 font SSJ-PK74820000a0f-Identity-H   ToUnicode=True
```

三者 **`ToUnicode` 均存在**，但 CMap 内容错乱 → 抽出来是 `잰!!퇔` / `犌犅１９６４１` / `!"!""#!`。

**关键认知（通用，以后处理任何 PDF 都适用）**：
> PDF 的「**显示**」和「**复制 / 搜索**」是**两套机制**：
> - **显示**靠嵌入的字形（glyph）——所以眼睛看到的是正常的
> - **复制 / 搜索**靠 ToUnicode 映射——这里坏了，所以复制出来是乱码
>
> 这就是"**能看不能复制**"类 PDF 的成因。**本批 5 份正属此类。**

**用户实测验证（决定性实验）**：在阅读器里选中 GB2716 第 2 页文字 → 复制 → 粘贴到记事本 → **结果为乱码**。证实"复制原文"路线**不可行**。

**由此确定 v2 正确做法**：
1. 图像层是好的 → 任何"**从图像重新取字**"的办法都能救（OCR / 视觉模型 / 人眼手打，原理相同，区别只是"谁来识字"）。
2. **GB2716 + GB5009.227**（判定链命根子）：截图 OCR 或看屏手打 → **人工逐格核对** → 写入 corpus 笔记。
3. **其余 3 份**：先确认是否在判定链上，不在则放弃（守"只收用得上"铁律）。
