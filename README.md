# FoodQC-Agent · 食用油中控质检辅助智能体

> 毕业设计项目 —— 基于领域知识图谱与大语言模型的食用油中控质检辅助智能体
> 切入场景：**酸价 / 过氧化值异常的判读与根因溯源**
>
> **当前进度**：W2 Day 12 已完成（2026-10-14）｜成熟度 **L3 知识库驱动**
> **当前能力**：模型会**自己先查语料库再作答**，答案带标准出处；查不到就拒答；提问混淆了标准体系时还会**主动质疑**

---

## 这个项目要解决什么

食用油质检最怕的一件事：**通用大模型会一本正经地编数字**。

第一天的实测就是铁证 —— 直接问模型"一级大豆油酸价限值是多少"，它答 **`0.20 mg KOH/g`（错误，属版本混淆型幻觉）**；而让它调用工具去查标准库，正确值是 **`0.50`**（GB/T 1535—2026 表 4）。

FoodQC-Agent 的回答是：**模型负责理解与组织语言，权威数字和判定结论一律由代码产出。**

---

## 四条核心设计原则

| # | 原则 | 落地方式 |
|---|---|---|
| ① | **模型不算数，代码算数** | 限值取自标准库，判定由代码比大小，模型只做解释 |
| ② | **答案必带出处** | 每个数值必须能追溯到国标条款，可翻回原文核对 |
| ③ | **只读不写源数据** | Agent 不修改任何原始质检记录 |
| ④ | **低置信度 / 安全指标强制转人工** | Agent 辅助查证，**绝不自动放行** |

## ★ 亮点一：四级防护实证证据链（Day 8）

把工具置于**故障态**，实测模型的退化行为与各级防护的真实效果：

| 阶段 | 约束载体 | 模型真实行为 | 可靠性 |
|---|---|---|---|
| **A** | 无 | 工具失效后**偷偷自己心算 60%，还照样判"合格"** | ❌ 危险 |
| **B** | 错误提示带"可用工具" | 第 2 步自己改对工具名，完成自愈 | 🔶 可用 |
| **C** | System 提示词约束 | 拒答转人工，但属"概率性听话" | 🔶 软约束 |
| **D** | **代码硬闸门** | 系统直接拦截输出，模型无发言权 | ✅ 100% |

**核心结论**：提示词层的规矩不但概率性生效，**还会互相打架**（C 阶段那条"失败即拒答"直接掐死了 B 阶段的自愈能力）。真正可靠的约束必须**下沉到代码**。

## ★ 亮点二：记忆支柱 —— 从"死表"到"可检索"（Day 10–12）

### 语料库规模
`corpus/` 共 **11 个文件**，覆盖 **18 份国家标准**：8 份逐格核对 + 6 份登记索引 + 4 份方法标准正文提炼。

所有限值均：① 从 PDF 原文**逐格核对**（中文乱码时改用页面渲染 + 视觉核对）；② 用**官方平台交叉验证**（国家食品安全风险评估中心 / 全国标准信息公共服务平台 / 食品伙伴网 / USDA 官方英译版）。

### 关键结论
> **一级浸出大豆油：酸价 ≤ 0.50 mg/g、过氧化值 ≤ 0.13 g/100g**（GB/T 1535—2026 表 4）
> ⚠️ **别把 GB 2716 的 3 当成一级的限值** —— GB 2716 是"食用植物油"整体底线，产品标准更严时从产品标准。这也是 Day2 模型答错的根本原因：**它分不清两套标准**。

### chunk 粒度的决定性影响（可复现的对照实验）
| | 优化前 | 优化后 |
|---|---|---|
| 检索次数 | 3 次 | **1 次** |
| 最高相关度得分 | 120 | **162** |
| 能否取到关键数值 | ❌ 被元数据挤出截断区 | ✅ 直接命中 |
| 结果 | 拒答 | 完整正确答案 |

> **结论：检索质量的瓶颈常在"怎么切块"，而非模型本身。**

## ★ 亮点三：它会在三种情形下守住底线（Day 12 实测）

| 情形 | 系统行为 | 证据 |
|---|---|---|
| **查得到** | 给结论 + 出处（精确到原文第几页）+ 完整限值 + 主动提示易混用的标准 | `docs/12` |
| **查不到** | **拒绝下结论**，说明"未能查到依据"，并指出**该核对哪一页**、警告勿套用旧版数值 | `docs/10–11` |
| **问错了** | 开口指出提问**"对象错配"**：① 无关领域明确拒答并给出正确标准线索 ② 相关部分反而给出双标准并行判定 ③ 结尾反问确认实际检测对象 | `docs/13–15` ⭐ |

> 在质检场景中，**一线人员拿错标准是真实风险**。系统能指出"你可能混淆了标准体系"，比顺着错误前提作答有价值得多。

## 快速开始

```bash

cd foodqc-agent
```

## 运行示例（Day 12 实际输出）

**输入**：依据 GB/T 1535—2026，一级浸出大豆油的酸价限值是多少？若实测 0.62 mg/g，是否合格？

**输出（摘要）**：
```
[第1步] 调 lookup_from_corpus("GB/T 1535 一级浸出大豆油 酸价 限值")
        → 命中 limits.json → GBT1535-2026 → 浸出大豆油_表4（得分 162）
[第2步] 调 calc("0.62 > 0.5") → True

最终答案：结论：不合格。
  • 限值出处：GB/T 1535-2026 表 4（原文第 5 页）— 酸价 一级 0.5（二级 2.0、三级 3.0）mg/g
  • 比对：实测 0.62 > 限值 0.5 → 不合格
  • 补充提示：该限值适用于浸出大豆油表4；压榨大豆油见表3，2026 版未规定酸价限值，切勿混用；
    大豆原油酸价 4.0（表2），不可用于成品油判定
```

## 安全与合规说明

- `.env`（含 API Key）、`.venv/`、`__pycache__/` 已在 `.gitignore` 中，**不会进入版本库**；克隆后需自行配置 `.env`。
- **质检场景定位**：Agent 仅作辅助查证，**最终放行权归代码与人工** —— 这是本项目区别于普通 AI 问答类毕设的关键设计。
- **语料来源**：均为公开发布的国家标准，限值经原文逐格核对与多平台交叉验证，**不含任何企业内控数据或实习数据**。
