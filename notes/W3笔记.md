## Day15 · judge 判定工具 + A/B 实测（2026-10-18 写码 / 10-19 跑通）

### 一、做了什么

1. **写 `judge_tool.py`**：把"实测值 vs 限值谁大谁小"这件事从模型手里收回代码。
2. **写 `test_judge.py`**：6 条回归 case（3 条不达标 + 3 条合格，含 2 条边界"正好等于限值"）。
3. **接进 `mini_agent_safe.py`**：`TOOLS_IMPL` 加一行 + `tools` 清单加一项。
4. **跑 A/B 对比**，拿到两组真实输出（见第五节）。

### 二、第一版是错的：方向判反

W2 计划里给的参考实现：

```python
return f"{'超标' if value > lim else '合格'}（实测{value} vs 限值{lim}）"
```

拿 GB 1350-2025 表 1 的真实数据一跑：

```
出糙率 二等    实测 76.5   vs 限值 ≥77.0   -> 合格   ❌ 应判"不达标"
整精米率 一等   实测 45.0   vs 限值 ≥50.0   -> 合格   ❌ 应判"不达标"
杂质含量      实测 1.5    vs 限值 ≤1.0    -> 超标   ✅
水分含量      实测 14.2   vs 限值 ≤13.5   -> 超标   ✅
```

**原因**：它只认上限型（≤），遇到下限型（≥）会判反。

**为什么这是致命的**：GB 1350-2025 表 1 共 7 项限值 —— 出糙率 ≥、整精米率 ≥ 是下限型，杂质/水分/黄粒米/谷外糙米/互混率 是上限型。**7 项错 2 项，而且全判成"合格"= 放行不合格原粮。**

> ⭐ 品控里，**方向性错误比数值错误严重一个数量级**：数值错了你能对出来，方向反了整批货已经进仓。
> 所以硬闸门不是万能的，**判定逻辑本身必须人工审**。

### 三、修好之后的代码

```python
if "≥" in limit_expr:        # 下限型
    ok = value >= lim
elif "≤" in limit_expr:      # 上限型
    ok = value <= lim
else:
    return f"无法判定：限值里没有 ≥ 或 ≤（{limit_expr}）"

return f"{'合格' if ok else '不达标'}（实测{value} vs 限值{limit_expr}）"
```

三个要点：
- **`>=` / `<=` 都含等号** —— 标准里"等于限值"算达标。改成 `>` 会把压线的判成不达标。
- **`else` 不硬猜**，直接"无法判定" —— 安全侧默认，比猜错强一百倍。
- **结论收在最后一个 `return`** —— 两个分支不各写一句，以后加"警惕/复检"档位只改一处。

### 四、接进 Agent 踩的坑：`tools` 和 `TOOLS_IMPL` 是两个东西

第一版只改了一半：

```python
TOOLS_IMPL = {"calc": calc, "judge": judge}     # ✅ 代码能执行
tools = [{ ...calc... }]                        # ❌ 模型看不见 judge
{ ...judge... }                                 # ← 孤立的字典，谁也没引用
```

程序照跑不报错，模型就是不调 `judge`。**这种 bug 是静默的**——不看代码就以为"judge 没用"。

**自检办法（不跑主程序、不花钱）**：

```bash
python -c "src=open('mini_agent_safe.py',encoding='utf-8').read(); ns={}; exec(src.split('messages = [')[0], ns); print([t['function']['name'] for t in ns['tools']])"
```

正确输出：`['calc', 'judge']`

| | 作用 | 少了会怎样 |
|---|---|---|
| `TOOLS_IMPL` | 给**代码**的执行索引 | 代码执行不了 |
| `tools` | 给**模型**的说明书 | 模型看不见、不会调 |

**两个都要，少一个就废。**

### 五、A/B 实测结果

**题目（两组完全一样）**：稻谷出糙率实测 76.5%，二等品要求 ≥77.0%，这批合格吗？

#### A 组 · `USE_JUDGE = False`（只有 calc）

```
[第1步] 调 calc({"expression": "76.5 - 77.0"}) = -0.5
最终答案: **结论：不合格。**

判定依据：
- 实测出糙率：76.5%
- 二等品标准：≥77.0%
- 差值：76.5 - 77.0 = **-0.5 个百分点**

实测值低于二等品下限 0.5 个百分点，未达到 ≥77.0% 的要求，因此按二等品判定为**不合格**
（不满足二等品出糙率指标）。

补充说明：以上仅为出糙率单项判定。整批等级判定还需结合水分、杂质、整精米率、黄粒米、
色泽气味等其他指标综合确定；若仅为不达标 0.5 个百分点，也可能只体现在降等
（如降为三等品），具体请按对应等级标准复核。
```

#### B 组 · `USE_JUDGE = True`

```
[第1步] 调 judge({"value": 76.5, "limit_expr": "≥77.0"}) = 不达标（实测76.5 vs 限值≥77.0）
最终答案: 这批稻谷**不合格**。
- 出糙率实测：76.5%
- 二等品要求：≥77.0%
- 判定结果：未达标（低于限值 0.5 个百分点）

建议按规定降等处理或作其他处置，具体请以检验报告和收购标准为准。
```

### 六、⭐ 真正的发现：两组都判错了

对照 GB 1350-2025 表 1（`gb-bot/_dump_GB1350-2025.txt` 第 153–168 行）：

| 等级 | 1 等 | 2 等 | **3 等** | 4 等 | 5 等 | 等外 |
|---|---|---|---|---|---|---|
| 出糙率/% | ≥79.0 | ≥77.0 | **≥75.0** | ≥73.0 | ≥71.0 | <71.0 |

**76.5% 落在 3 等区间** —— 它 ≥75.0，只是达不到 ≥77.0。

**正确结论**："达不到二等，符合三等要求，应降等收购。"
**两组的结论**："不合格。"

> "不合格"在国标语境里指**不符合标准（落到等外）**；不足某一等级应说"达不到该等级"。
> **现场一句话之差：一句是降价，一句是退货。**

更讽刺的是 —— **A 组自己在补充说明里写对了**（"可能降为三等品"），但没把这句话用在主结论上。
B 组则自相矛盾：先说"不合格"，又说"建议按规定降等处理"（既然不合格，为什么要降等？）。

### 七、这套 A/B 到底证明了什么

**先说诚实结论：这次 A/B 没有证明 `judge` 的价值。**

样本太简单 —— 题目里已经写明"二等品要求 ≥77.0"，方向没有歧义，模型这次判对了。

**单例 ≠ 分布。** 模型有随机性，这次对不代表下次对。要证明价值，得 **5 个指标 × 各跑 10 次**，看判对率。

**但它证明了另外三件事，每件都比"judge 好不好"重要：**

| | A 组（只有 calc） | B 组（有 judge） |
|---|---|---|
| 输出长度 | 长 5 倍，夹带无出处推断 | 短，只报工具结论 |
| 判定权 | 模型自己比大小 | 代码比，**可回归测试** |
| 可审计性 | 过程看不见 | 一步一条日志 |
| 一致性 | 每次可能不同 | 每次一样 |

**最值钱的一条**：A 组会自己补话，而且补的话可能比主结论更准 —— **但没有出处，无法核验**。
这正是「答案必带出处」这条原则的真实由来。

### 八、⭐ 新洞见：`judge` 的边界在哪

**`judge` 只回答「跟某一个限值比，达不达标」——它不知道等级体系。**

"定几等"是**另一层逻辑**：要在同一指标的**多档限值里定位它落在哪一档**，不是和一个限值二分。

- 模型知道等级体系（A 组说漏嘴了），但说出来没出处、不稳定
- `judge` 稳定，但只会二分
- **两者都不够 → 需要第三层：定等函数**

这是毕设"判定链"的真正难点，是自己撞出来的，比任何文档教的都记得牢。

**待办**：`judge_grade(value, limits_list)` —— 多档限值 → 返回所属等级 + 依据档位。留到 Day21 接 `limits.json` 时一起做。

### 九、费曼抽查（Day15 三问，记录批改结论）

| 问题 | 我的答案 | 批改 |
|---|---|---|
| 标准里"等于限值"为什么算达标？代码里哪个字符保证的？ | 原文写 ≥/≤，代码也用 ≥/≤；改成 >/< 会把等于限值的判错 | ✅ 对，但要抠清：`"≥" in limit_expr` 里的 **Unicode 字符 `≥`** 是判方向，`value >= lim` 里的 **ASCII 两字符 `>=`** 是判达标，**两码事** |
| 把比大小收回代码图什么？代码会不会"看错"？ | 代码是执行者不会出错；但方向写死就是早上那个 bug | ⚠️ 半对。"代码不会出错"这句要收回：**代码不会临场发挥出错，但会把写错的规则一字不差执行一千遍**。模型的错随机、不可复现；代码的错确定、可复现、**能被测试抓出来** |
| `else` 为什么拒答不猜？猜的最坏后果？ | 安全侧默认，猜反了等于反转结论；最坏是镉这种重金属被放行流到餐桌 | ✅ 直觉对，但**镉的例子举反了**：镉是**上限型**（GB 2762-2022 稻米 ≤0.2 mg/kg），不是下限型 |

**⭐ 由此得到的判断规则（记住这条）：两类限值的错误代价不对称**

| | 典型指标 | 判错的后果 |
|---|---|---|
| **下限型 ≥** | 出糙率、整精米率 | **经济损失**（降等、扣价、出米率低）—— 赔钱 |
| **上限型 ≤** | 镉、无机砷、黄曲霉毒素、水分 | **健康风险**（放行超标粮上餐桌）—— 害人 |

因为**安全指标几乎清一色是上限型**（毒物越多越危险），**下限型基本是"越高越好"的品质指标**。

早上那个 bug 把一切都当上限型判，所以错在**下限型**这一侧：**只赔钱，没害人**。运气好。反过来写才是要命的那种。

> **判反方向的时候，先问自己一句：我这是在赔钱，还是在害人。**

### 十、留下的坑（还没修，别忘）

1. **区间限值**：`"13.5～14.0"` 这种，`re.search(r"[\d.]+")` 只取第一个数；且 `"≥13.5～≤14.0"` 只会命中第一个分支。
2. **符号变体**：PDF 抽出来可能是 `">=77.0"`，会掉进 `else` 被拒答（安全侧，但会误拒）。
3. **定等缺口**：`judge` 只会二分，不会定等（见第八节）。
4. **测试覆盖**：6 条 case 只覆盖单限值，没覆盖区间和符号变体。
