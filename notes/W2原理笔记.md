## 二、新词（大白话版）

| 名词 | 大白话 |
|---|---|
| **Agent 智能体** | 不是"问一句答一句"，而是会自己**循环**"想 → 调工具 → 看结果 → 再想"去完成任务的 AI |
| **ReAct** | Reason（思考）+ Act（行动）的循环。我 Day5 手写的 `mini_agent.py`、**Day8 的 `mini_agent_safe.py` 就是 ReAct 的最小实现** |
| **Reflection 反思** | 模型自己检查自己上一轮答得对不对、发现不对就改。我的 `for step in range(MAX_STEPS)` 循环里"把工具结果丢回给模型让它想下一步"就是反思 |
| **Tool Use 工具调用** | 自己不会算 / 不知道的，去调外部函数。`lookup_limit`（查国标）、`calc`（算百分比）是工具，`TOOLS_IMPL` 字典是工具箱 |
| **Planning 规划** | 把大任务拆成子步骤再一步步做。毕设"异常值 → 根因溯源"就是一条规划链 |
| **Multi-Agent 多智能体** | 几个 Agent 分工（一个写一个审）。⚠️ 在我的「不学清单」里，只了解概念 |
| **Workflow 工作流** | 流程**预先定死**的方案（串步骤 / 分类分发 / 并行）。比 Agent 便宜、可控 |
| **四件套** | 大模型（脑）+ 记忆（知识仓库）+ 工具（手）+ Skill（工艺规矩）。毕设架构就坐落在这套框架里 |

## 三、两大材料的核心结论

### ① 吴恩达四大设计模式（我已亲手写过前两种）

1. **Reflection 反思** —— 像写完作文自己读一遍挑错。落点：`mini_agent_safe.py` 的主循环。
2. **Tool Use 工具调用** —— 像不会心算就掏计算器。落点：`lookup_limit` / `calc` + `TOOLS_IMPL`。
3. **Planning 规划** —— 像做菜先看菜谱分步。落点：毕设根因溯源链（W3 后强化）。
4. **Multi-Agent 多智能体** —— 不学，仅了解。

### ② Anthropic《Building Effective Agents》：一句话 —— **大多数情况根本不需要 Agent**

- 两档方案：**Workflow**（流程预设、确定）vs **Agent**（模型自己动态决策，最贵最难控最易幻觉）。
- 建议：从"最简单能用的"开始。能一次调用解决就别上 Agent；步骤固定就用预设工作流；**只有任务复杂、不可预测、需要临场决策时才上 Agent**。
- **对我毕设的意义（答辩直接用）**：食用油质检高风险、要签字担责 → 所以我的设计是"**Agent 辅助查证，放行权收归代码和人工**"。模型可以反思、可以调工具，但"合格/不合格"这个最终动作不能交给模型自主决定。

### ③ 为什么"数值计算不能让模型做"——用 Day2 幻觉当证据

- **Day2 裸问**：模型编出 `0.20 mg KOH/g`（错的）。
- **Day4–6 工具调用**：查标准库得到 `0.50`（对的）。
- **Day8 实验 A（铁证）**：工具一失效，模型**偷偷自己心算 60%，还照样判"合格"**——幻觉换了条通道复发。截图 `docs/06_工具失效_模型退回手算.png`。
- 结论：**模型不算数、代码算数**，这条原则必须靠代码强制，不能靠提示词叮嘱。

## 五、费曼实战第 1 题（2026-10-10）——面试官灵魂追问

**题目**：*"你这个 FoodQC-Agent，说白了不就是问 DeepSeek 一个问题吗？我自己打开对话框问'一级大豆油酸价限值是多少'，跟你的系统有啥区别？"*

### 我的初答（原话大意）

> 不是这样的，它有自己的一个领域专业知识库；豆包这种通用大模型是联网搜索甚至有时候都懒得联网给你搜索。我这个 Agent 工作的时候是强制先检索知识库，而且不会像豆包 DeepSeek 对话模型一样找不到会乱答，知识库中没有的东西就说没有。

### 答得漂亮的地方 ✅

全程没堆术语，外行听得懂。抓住了四点：有专业知识库（记忆）、通用模型懒得搜就乱编、强制先检索（顺序约束）、没有就说没有（承认边界）。

### 三个 gap（这才是真要补的）🔴

**Gap 1：查到之后谁来判断？**
不能把"限值 0.25 + 实测 0.15"丢给模型让它心算判定。**判定交给代码**比大小，模型只负责把结果说成人话；且**答案必须带出处**（出自 GB 2716 第几条，能翻回原文核对）。

**Gap 2：查到了也不一定放行。**
质检要签字担责。涉及安全指标或置信度不高 → **必须转人工**。Agent 是辅助，不是放行口。

**Gap 3（最值钱）：我说的"强制"其实还没真正做到。**
"找不到就说没有"目前主要只是 SYSTEM 提示词里的一句话，是**软约束**。Day8 已经证明：提示词叮嘱"工具失败必须拒答"时，模型要么第一步就躺平拒答、要么（实验 A）**偷偷自己心算还判合格**。真正拦住它的是**代码**（`failed >= MAX_RETRY` → break），那一刻模型连说话的机会都没有。

| | 靠什么 | 可靠吗 |
|---|---|---|
| 现在的"找不到就说没有" | 提示词吩咐（软） | 🔶 这次听话，下次不一定 |
| 真正的可靠版 | 代码拦截：没检索到就直接拒绝输出（硬） | ✅ 100% 拦得住 |

### ⭐ 升级版满分答案（背这句）

> "靠两件事：**第一，检索是写进流程里的**——它给出的每一个限值都必须附'出自 GB 2716 第几条'，能翻回原文核对，编不出来。**第二，规矩不看它自觉，靠代码兜底**——我做实验时发现，只靠提示词叮嘱'查不到就说不知道'，模型在工具出问题时仍然偷偷自己算了个合格出来。所以我改成代码判断：检索不到、或者工具连续失败，系统直接拒绝给出结论，转人工。模型再想绕也绕不过去。"

### 记住用的类比 🥡

> **通用大模型 = 嘴快、没培训过的路人**，你问"这油合格吗"他张口就来，听着挺专业，其实拍脑袋编的。
> **FoodQC-Agent = 新来的质检员**，上岗前我给他配了三样：① 一本**标准手册**，遇到问题必须先翻，不许凭印象；② 手册上没有就**不许猜，必须说"没有"**；③ 查完**拿计算器算**（判定由代码做），但**最终签字权在师傅手里**（转人工）。
> 关键是——这套规矩**不是口头吩咐**，是把计算器焊在他手上、把"没查到就不许输出"写进了流程里（代码硬闸门），他想偷懒绕都绕不过去。
